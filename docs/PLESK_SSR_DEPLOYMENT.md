## Git deployment

Plesk Git must update a source checkout that is separate from the active document root. The post-deployment action invokes `scripts/deploy-ssr.sh` with:

    SSR_GIT_DIR=<absolute Plesk Git checkout root>
    SSR_APP_DIR=<Plesk Git checkout root>/ssr
    SSR_RELEASES_DIR=<stable absolute release directory>
    SSR_CURRENT_LINK=<stable absolute symlink path>
    SSR_SHARED_DIR=<stable absolute directory containing .env and storage>
    SSR_PHP_BIN=<optional absolute PHP 8.3+ CLI path>
    SSR_COMPOSER_BIN=<optional Composer executable path>
    SSR_HEALTH_URL=https://erphpro.com/health

Before enabling this hook, prepare an existing known-good release under `SSR_RELEASES_DIR`, a `SSR_CURRENT_LINK` symlink pointing to it, and `SSR_SHARED_DIR/.env` plus persistent `SSR_SHARED_DIR/storage`. Set the Plesk document root to `<SSR_CURRENT_LINK>/public`. `SSR_RELEASES_DIR` and the parent directory of `SSR_CURRENT_LINK` must be on the same filesystem. The Git checkout/source tree must not itself be the live document root. These Plesk paths, the shared data copy, file ownership, and the first-release rollback must be verified before changing production settings.

The hook requires every path above plus `SSR_HEALTH_URL`; it exits before building if configuration is incomplete. It selects PHP from `SSR_PHP_BIN`, `/opt/plesk/php/8.3/bin/php` when executable, or `PATH`, then validates PHP 8.3+ and required extensions. It archives the exact 40-character Git commit's tracked `ssr/` tree into a temporary directory under `SSR_RELEASES_DIR`, links the shared `.env` and `storage`, installs locked dependencies, checks the production migration ledger without applying migrations, and builds release-local config/route/view caches. Pending or uninspectable migrations stop before promotion. The release directory is made immutable by its commit-SHA name; an existing release is not overwritten.

Promotion atomically replaces `SSR_CURRENT_LINK` only after the build passes. The public health response must contain `status=ok`, `database=ok`, `cache=ok`, and a `release` matching the commit SHA. A failing health check triggers an exit trap that restores the previous symlink and retains the SHA-marked release; a later deployment of that same SHA can verify and retry the prepared release without overwriting it. Incomplete or mismatched release directories are refused. Old releases are retained and are not pruned by this hook. A host crash or forced kill between symlink replacement and health verification cannot run the trap, so a production cutover still requires an independently rehearsed rollback. Database migrations and initial support-content seeding remain separate, approved operations after a verified recovery point. Deployment logs must be retained. This local hook behavior does not establish the Plesk document root, runtime permissions, PHP-FPM/OPcache identity, or successful production execution.
